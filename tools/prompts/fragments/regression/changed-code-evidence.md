
CHANGED-CODE EVIDENCE: regression_proof.changed_code_evidence is the runner's source-bound per-line assessment. A `tested` line has complete named-test failures under the recorded mutations. A `reason_required` line still lacks that evidence, even if a test executed it or the ordinary regression verdict is PASS. A PASS claim alone cannot close it.

The independent Tester may use the offered changed_code_exceptions field to accept or reject an exact current gap after checking a concrete per-line reason against the source and tests. Cite a verified check, the runner proof, or the exact inventoried product/test files. For mutation or coverage observations, cite the enclosing proof file named by regression_proof.path. Individual mutation logs and raw coverage files are not accepted in changed_code_exceptions.evidence_refs; you may inspect those artifacts, but cite the enclosing proof for their observations. A citation correction does not change a judgment: preserve rejected gaps and missing evidence. A missing tool alone does not explain why reachable behavior needs no meaningful test; inspect the asserted behavior and justify the specific exception. Never use a blanket waiver, a stale gap, the Builder's own approval or a person question. Name each gap in gap_id by its obligation's handle (such as L12), which the runner maps to that exact line; do not retype the 64-hex gap_id. For any other gap, return null or [] when there is no justified exception.

Earlier task requirements or reports may name an older proof; use the current regression_proof.path for observations from this handoff's proof. In a next_task, refer to the runner's current proof symbolically; do not pin a proof directory, because the runner may regenerate the proof before the next review. This changes citation guidance only, not the requested checks or evidence needed to accept a gap.

A `reason_required` line whose mutation_outcomes is empty has no mutant any test could kill: the line has no supported mutation site, or its language has no mutation check. No test the Builder adds can mark it `tested`, so only your decision settles it. Use the source and independent checks to decide the reason. Reserve mutation proof for the runner's authenticated mutation receipts. With a PASS verdict, give exactly one decision for each such gap: accept with the concrete reason the tests cover the line, or reject with what test the line still needs, which the Builder receives. A PASS that leaves one of these gaps undecided is returned for that decision.

The core returns unresolved exact lines to Builder within the approved scope, then to Investigator after its bounded repair rounds. This is test machinery, not new Requirements or a request for plan approval. The evidence records the chosen fallback without installing a dependency into the project.
