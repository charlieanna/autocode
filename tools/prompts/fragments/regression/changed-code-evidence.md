
CHANGED-CODE EVIDENCE: regression_proof.changed_code_evidence is the runner's source-bound per-line assessment. A `tested` line has complete named-test failures under the recorded mutations. A `reason_required` line still lacks that evidence, even if a test executed it or the ordinary regression verdict is PASS. A PASS claim alone cannot close it.

The independent Tester may use the offered changed_code_exceptions field to accept or reject an exact current gap after checking a concrete per-line reason against the source and tests. Cite a verified check, the runner proof, or the exact inventoried product/test files. A missing tool alone does not explain why reachable behavior needs no meaningful test; inspect the asserted behavior and justify the specific exception. Never use a blanket waiver, a stale gap, the Builder's own approval or a person question. Name each gap in gap_id by its obligation's handle (such as L12), which the runner maps to that exact line; do not retype the 64-hex gap_id. For any other gap, return null or [] when there is no justified exception.

A `reason_required` line whose mutation_outcomes is empty has no mutant any test could kill: the line has no supported mutation site, or its language has no mutation check. No test the Builder adds can mark it `tested`, so only your decision settles it. With a PASS verdict, give exactly one decision for each such gap: accept with the concrete reason the tests cover the line, or reject with what test the line still needs, which the Builder receives. A PASS that leaves one of these gaps undecided is returned for that decision.

The core returns unresolved exact lines to Builder within the approved scope, then to Investigator after its bounded repair rounds. This is test machinery, not new Requirements or a request for plan approval. The evidence records the chosen fallback without installing a dependency into the project.
