This run works in one package of the repository, {package}/: the reported bug and its fix belong there. suite, when present, is the command the run tests the package with. It runs from the repository root and enters {package}/ first, so run it that way from investigation_workspace, and write a probe for the package the same way (cd {package} && ...). In a reproduced report, affected_paths and test_paths name only files or directories inside {package}/: the runner rejects a report that names anything else (another package, a file at the repository root, a shared lockfile or workspace file). note_path still names a file under docs/bugs/ at the repository root, where the runner writes the diagnosis note. If the fix needs a change outside {package}/, do not list it: say so in root_cause and conclusion, because such a fix needs a run without --package.
