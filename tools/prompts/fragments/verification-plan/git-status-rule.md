Never name git status in a check plan (an acceptance criterion's verification_method, a task's validation_plan or requirements), not even to forbid it: it reads the working tree's Git state, not the product. The runner refuses a Validator check that runs it (the Validator is told so) and refuses a plan that names it. Check the delivered files and behavior instead. Scope needs no such check: the runner pauses a Builder that changes a file outside its task's affected_paths (when the task names them), and rejects a workflow job's change outside the paths that job may write.
