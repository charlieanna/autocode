# Retained report recovery (#4076)

## Scope

An unchanged completed report can be revalidated under a changed runtime while
its exact report-rejection incident is held. Its source, artifacts, handoff,
attempt, incident, accounting and interrupted-work frontier are rechecked by
the locked owner. The accepted report and checked incident commit together;
the ordinary final work guards remain authoritative. A rejected report records
the current diagnostic and stays held without another attempt or allowance.
The status observation is bounded and read-only. The editor takes only the
explicit, token-bound automatic offer; a restart after the atomic acceptance
rechecks the saved owner before continuing.

The launch record projects four route values with `dict.get`, losing whether a
null value was absent or explicitly null. Its exact original handoff digest
still binds the complete settings. Revalidation considers only those bounded
projection preimages, retaining unprojected settings, and accepts a candidate
only when the full original handoff digest matches. Other changed inputs remain
held. Older exact-route records keep their existing interpretation.

This path deliberately holds an accepted report that would create a different
person-decision boundary; that boundary is not silently advanced. It does not
grant a retry of a timed-out or uncertain provider (#3963).
