# Shared scratch-copy follow-up

The merged #3992 suite exposed two independent false refusals in shared scratch preparation. A deleted tracked path has the source identity `deleted` but has no physical file in the copied tree. Also, a probe can legitimately place its owned scratch Git worktree under an unignored workspace path; the post-copy workspace snapshot then sees that worktree as a new nested repository.

The correction compares deleted paths with actual absence, preserving refusal if any copy resurrects one. The post-copy comparison disregards only the exact newly created owned worktree, only when it was absent from the original inventory and not within an explicitly selected source scope. A new sibling source remains a mismatch. Review-specific source admission still rejects tampering before a patch, with its existing review-specific error.

The two positive controls failed on master `6b803f17e`; resurrection and neighboring-source negatives already failed closed there. Local verification passed the full protected-oracle and design-probe modules (46 tests), review-proof, review-mutation, copy-identity and source-snapshot modules (82 tests), workflow-scope Ruff and mypy (990 files). Exact-head CI remains pending. The historical #3992 Ubuntu suite failure is retained in `/private/tmp/autocode-3992-suite-failure.log`; do not represent it as green.

Focused CI selection previously omitted the indirect protected-oracle, design-probe and review-proof consumers of shared scratch preparation. Both shared source-copy modules now select those consumers and their worker/link safeguards; a selection regression fails on master. The selection and suite-runner modules passed 205 tests.

A replaced parent symlink revealed a separate reporting regression: the stronger copy guard correctly refuses to follow it before either protected-test half starts, but its raw `ValueError` escaped instead of entering source recovery. The guard now identifies that specific unsafe-source-path error and transports it as the existing `PAUSED_SOURCE_UNAVAILABLE` refusal, including through a real owned worker; it never follows the link, launches a check or writes the external target. The protected-link regression and worker transport controls failed before this correction. All 60 protected-link/copy/source tests and 142 CI-selection tests passed locally.

An independent review found the same unsafe-parent error could arise while checking the captured review source, before the generic copied-file check. A controlled copied-tree regression failed before the fix; the review-source check now uses the same narrow source-refusal translator while preserving ordinary review mismatch errors. Its complete review/protected-link/copy/source/mutation run passed 94 tests; Ruff and mypy passed. The full previous-head focused run passed 803 tests in 34 modules; the current head must still pass exact-head CI.

A real scratch refusal formerly offered a futile Resume; the regression now verifies no offer, no saved-state mutation on Resume, and an offer after source becomes safe. Separate controls retain ordinary source recovery, tracked symlink leaves, disposable-copy-only recovery and unrelated ValueErrors.
