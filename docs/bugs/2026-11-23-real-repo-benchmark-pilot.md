## Humanize stop (AutoCode defect, not model error)

The delivered fix was correct (oracle 5/5, Investigator confirmed every test passes with the project's configured
test command). The plan's validation step named a bare `python3 -m pytest tests/test_number.py -q`; the runner
replays it in a clean copy of the source, which leaves out gitignored files, and Humanize's
`src/humanize/_version.py` is generated by hatch-vcs and gitignored. So the step can never pass, three Tester
attempts were rejected for it, and the run paused asking the person about machinery. Any project using
setuptools-scm / hatch-vcs generated version files would hit the same thing.
