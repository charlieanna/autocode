# Configured models rejected by historical policy

AutoCode hid `mimo-token-plan/`, free, Flash and highspeed routes even when the
provider listed them. The continuous conversation profile additionally rejected
all deviations from its exact model/effort pins. The scorer treated MiMo token-plan,
GLM 5.2 and models outside a fixed subscription list as failures. Reviewer recovery,
the hybrid fixture router and legacy Codex dashboard had separate model allowlists.

Model pins are now defaults. The catalogue offers every well-formed provider route;
explicit handoff overrides preserve their model and reasoning effort. Conversation
and visual-route validation accept configured models, and reviewer recovery can use
any already configured independent alternate route. Native dashboard model selection
accepts valid bare model names. The scorer records billing and ladder comparisons
without penalizing models for either. Its legacy `forbidden_seen` field remains an
empty list, and `all_subscription_only` describes recognized subscription prefixes
rather than deciding the model-routing score.

The built-in OpenCode connection check accepts OAuth, API authentication or explicit
API environment configuration. It neither copies credentials nor chooses a fallback
connection. Provider-configured auth requirements still apply. Actual model availability,
route syntax, immutable saved dispatch bindings and independent verification still
apply. This does not assert that every provider model can execute every task.

Offline coverage exercises MiMo token-plan completion through the CLI with an
API-authenticated checker, plus free/Flash and future model catalogue, handoff,
visual selection, fallback and scoring paths. No live model calls are needed.
