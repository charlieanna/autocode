# Investigator advice across a requested boundary pause

The heavy LedgerLab qualification queued a public pause while its Investigator
diagnosed a rejected combined B/C report. The Investigator finished and saved
concrete retry guidance. After `PAUSED_INTERVENTION` and public resume, the new
Tester prompt listed that report among the available evidence but omitted the
active `INVESTIGATOR GUIDANCE` block. The lifecycle retired the advice when the
run left RUNNING, even though the advised stage had not consumed it.

Requested boundary pauses now preserve applicable advice. Ordinary failure and
completion boundaries retain their existing retirement behavior, and successful
execution consumes its advice as before. The pause neither renews the spent
investigation identity nor changes an attempt allowance, budget or approval.
Execution advice is bound to the task, current task, source snapshot, contract
revision/hash and saved user input, so changed inputs refuse stale advice.
Legacy unbound execution advice is not promoted into current instructions.

The execution binding is generated by the core at interception, including during
replay; no model answer supplies or cites it. Replay therefore captures a fresh
binding from its own current inputs rather than accepting an old recorded hash.
Snapshots may be inline objects or saved artifact paths; the binding performs no
file read and does not substitute for source or evidence validation.

The public CLI regression holds a scripted Investigator at a real provider
boundary, submits a pause, resumes, and inspects the next provider's prompt.
It also requires the plan-approval gate and unchanged spent investigation count.
It fails on the base because the correction is missing (13.179 seconds) and
passes on the candidate (13.372 seconds). Separate regressions fail on base for
stale execution advice and the required CLI-consumer mappings. Linux lifecycle
tests pass, with the platform-specific native read-only sandbox case skipped.

The first changed selection ran 509 tests in 27 modules: two consumers exposed
an incorrect dictionary assumption for path-valued snapshots. The classification
module passed all 21 tests on unchanged master, confirming the candidate
regression. The corrected final affected selection passed **510 tests in 27
modules in 155 seconds**, including classification recovery, changed-code evidence,
planning-cycle recovery and the new public pause regression. Ruff check and format
passed for 3,265 files. The final patch SHA-256 is
`c1e996df523182c76efafad534e93d51a273556b3fe1af5ec6e1d6060292276b`
on base `c6b409ad59ba39a543386c0e8a40627959310a14`; only this note was updated
afterward. Earlier CLI fixture attempts stopped at unrelated planning allowances;
they are retained and are not counted as fail-on-base proof. The corrected test
pauses after the Investigator has already granted the next review, without a
fixture-specific allowance override.

Evidence is retained in the ignored
`.scenario-runs/orchestrator-heavy-live-20261105/` directory, including the saved
Investigator report, resumed prompt identity, base/candidate logs and failed
fixture attempts. This fix is not active in that ongoing Tester attempt, and
does not reconstruct advice that an earlier runtime already retired.
