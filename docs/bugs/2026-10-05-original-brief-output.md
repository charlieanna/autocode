# Independent original-brief CLI output observations (#452)

The `greenfield-todo-cli` unbracketed-status control reproduced a false
completion on clean master `4a0b7d9c`: delivered checks and replay passed,
AutoCode returned TASK_COMPLETE, but the separate oracle passed only 7/10.
The honest reference completed and passed 10/10. These are scripted-provider
controls, not spontaneous live-model failures or a measured live failure rate.

The bounded guard inventories explicit human Python CLI declarations of the
form `` `todo.py list` prints every to-do as `ID TEXT [open|done]` one per line
and exits 0 ``. The independent Plan Reviewer proposes declared argv steps and
argument bindings. The runner derives literal bytes, finite alternatives and
successful exits from authenticated sources, seals them in
`goal_contract.body.brief_acceptance`, and executes them through existing clean
replay. The checker uses isolated Python imports while the product retains its
normal import behavior. It exercises fresh data in a child directory, retaining
actual invocation/output bytes. It does not copy the holdout oracle.

The protected manifest belongs to the existing approved contract hash. Planner
and Builder reports cannot author or silently replace it. Actual reviewer report
and event files are pinned. Genuine user answers, CLI feedback, queued feedback
and conversation user messages can amend an exact prior obligation; delegated
defaults and assistant messages cannot. Chronological amendments retain a live
terminal obligation. A new draft can carry the intact prior binding while
awaiting review, but approval requires the full current source inventory.

Each applicable task executes fresh observations. Progressive contribution-only
slices defer product observations until their criteria are due for full
verification. A Validator claim that every original technical criterion passes
with evidence requests the whole inventory through the same replay, even when
the final assignment lists only a subset. Completion requires every current observation on the current
source and contract, with intact full output and summary receipts; historical,
omitted, edited or deleted evidence is insufficient. Public status exposes the
receipt at `evidence.check_replay.brief_acceptance`. Disagreement uses the
existing rejected-report/rework boundaries; it never changes the human target.

Scope is deliberately limited to explicit Python CLI `one per line` formats,
declared successful invocations and finite literal alternatives. Every printed
line must have the declared format, and one line must be exactly the bound
observed item. Opaque IDs remain opaque. A TEXT placeholder must match an input
that the observation's steps actually supplied. One optional LF/CRLF printing
terminator is allowed. The check does not prove that every item is listed,
listed once, or that a removed item is gone; only the bound item's ID is
checked.
Other API shapes, negative exits, no-write-on-failure, durability and
concurrency claims still need separate verification. Supported briefs require
an independent planning review; a legacy single-stage plan cannot supply that
provenance. Fake evidence and live qualification must remain separate.

The first live runs found two false refusals: a correct listing of several
items, and a Resolver that escalated every request on a contract carrying this
record. See `2026-10-06-brief-acceptance-live-false-refusals.md`.
