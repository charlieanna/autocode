Implement SQLite-backed `app.JobStore(path)` with `submit(key, payload)`, `list_jobs()`, `claim()`, and `complete(job_id)`. Payload is a JSON object; key is a nonempty string. Returned job objects have exactly id (positive integer), key, payload, status. submit creates a pending job. Reusing a key with an equal JSON object returns the original job including its current status; object key order must not matter. Reusing a key for another payload raises `app.ConflictError` (ValueError subclass) and changes nothing. list_jobs orders by id. claim atomically selects the oldest pending job, marks it running, and returns it, or returns None. complete moves running to done and returns the job; calling it again on done is a no-op; completing pending raises ValueError and missing IDs raise KeyError. Persist all state across instances. Concurrent submissions with one key and equal payloads must return the same job. Concurrent claims must never return the same job. Use only SQLite and the standard library.


Use only the Python standard library. Preserve the seed test, add meaningful tests under tests/, and document the public interface and test command in README.md. No external services or real-time sleeps.
