Implement this project: Build Journal(path), a durable SQLite event journal with reconstructible counter projections. append(event_id, key, delta) atomically appends a unique event and returns True; exact duplicate replay returns False, conflicting replay raises ValueError. delta is any integer excluding bool. state(snapshot_path=None) returns a dict of counter keys to summed deltas, preserving keys whose total becomes zero. Without a snapshot, replay events in sequence order. snapshot(path) atomically writes JSON with sequence (the last committed integer sequence, zero when empty), totals (the projection), and checksum, a SHA-256 hexadecimal digest of json.dumps({'sequence': sequence, 'totals': totals}, sort_keys=True, separators=(',', ':')).encode(). A subsequent state(snapshot_path) must start from a valid snapshot and apply only later events. Missing, malformed, invalid-checksum, structurally invalid, negative-sequence or future-sequence snapshots must be ignored and recovered by full journal replay; never rewrite the supplied snapshot during reads. Snapshots are local acceleration artifacts rather than an authentication mechanism. Reopening the journal and replaying after a snapshot must be deterministic; duplicate appends never change totals. Include tests for restart, negative deltas, exact replay boundaries, and corrupt snapshot recovery. No distributed replication or wall-clock event ordering is required.
